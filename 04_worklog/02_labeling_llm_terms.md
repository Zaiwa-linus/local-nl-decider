# ラベル付けに使う LLM と規約（jev、DeepSeek）

## jev の準備と規約の確認

- API キーをもらった。`.env` に置いた（`.gitignore` 済み）。`GET /v1/models` と `jev_sample.py` で動作を確認した（モデルは `jev-1.14.0` に上がっていた）
- Phase 2 の予行演習（MASSIVE の train 2,000 件に jev でラベルを付け、それで判定機を学習する）のために、01_scripts/07_jev_label.py を作った（規約の確認後に削除）
- 20 件だけで動作確認した結果:
  - 正解との一致: 17/20 件（85%）。外れたのは「距離」「おやすみ」「死についてのボルヘスの詩を理解したい」など、文だけでは判断しにくいもの
  - 速さ: 8 件ずつ並列に送って約 35 件/秒。1 件あたりの応答時間は平均 0.19 秒
  - 入力は 1 件あたり約 840 トークン（2,000 件なら約 170 万トークン、約 $0.07 の見込み）
- 公式ドキュメント（docs.typesafe.ai）と規約を読んで、`00_knowledge/01_jev/` を書き直した
- **規約（Master Customer Agreement §2.3(b)）で、jev の出力を使ったモデルの蒸留と、jev の出力をまねるようにモデルを学習させることが禁止されていた**
  - jev のラベルで判定機を学習するのは、これに当たる可能性が高い。2,000 件のラベル付けは実行しないことにした
  - 動作確認で作った 20 件のラベルも、学習には使わずに削除した
- そのほか、公式ドキュメントで分かったこと:
  - jev は主に英語で学習されていて、日本語は英語ほど安定しない
  - jev の確信度は「いちばん高い確率」ではなく、分布のとがり具合から計算した値。当たる確率として補正されているとは書かれていない
  - 最初の選択肢を選びやすい傾向がある

## ラベル付けに使う LLM の選び直し

- 目的は LLM の出力による学習データの蒸留なので、出力を別のモデルの学習に使ってよいと規約で認められている LLM を探した
- jev、OpenAI、Claude は、いずれも規約で禁止または制限されていた
- **DeepSeek API は、規約（Open Platform Terms of Service §4.2(3)）で「別のモデルの学習（モデルの蒸留など）」に使えると明記していた。これを使うことにした**
- 注意: 送ったデータは中国のサーバーに保存され、DeepSeek の学習に使われることがある。公開データなら問題ないが、個人情報や社外秘は送らない
- 比較の詳細: [00_knowledge/04_labeling_llm/](../00_knowledge/04_labeling_llm/)
- jev 用に作ったラベル付けのスクリプト（07_jev_label.py）は削除した
