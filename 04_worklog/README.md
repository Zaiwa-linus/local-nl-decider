## ここまでのまとめ

- **自然言語のラベル付けは、人がやっても判断がブレる。** 1 件の記事や意見に、どれも筋の通るカテゴリーが複数ある。どれを選ぶかは付けた人（や連載の編集者）の、その時の判断で決まる
  - livedoor で DeepSeek と正解が食い違った記事を 15 件読むと、DeepSeek のはっきりした間違いは 2 件。7 件は内容だけ見れば DeepSeek のほうが妥当、6 件はどちらとも言えた
  - 正解は「どの連載に載ったか」で、内容から一意に決まるラベルではない
- **そのブレに、説明だけで追いつくのは無理。** カテゴリーの説明をどれだけ書いても、付けた人の判断までは写せない
  - 先生（DeepSeek）の正解率は、説明だけで 64%、例を 5 件ずつ見せても 71%。蒸留した判定機も先生と同じところで止まる
  - 一方で DeepSeek 自身の判断はほぼ揺れない（同じ条件で付け直して 96% 前後一致）。ブレているのは LLM ではなく、正解の側
- **数字の見方**: 「正解との一致率」が低くても、判定機や LLM が悪いとは限らない。正解のラベル自体に、人の判断のブレが入っている
  - ただし、同じ人（同じ連載）が付けたラベルを数百件以上そのまま学習すると、判定機は 87% まで合わせられた（500 件でも 79%）
  - その人の判断に寄せたいなら、説明ではなく、その人が付けた例をたくさん集めるしかない
- **実際に使うときの考え方**: 「誰かの正解」に合わせ込むより、LLM（または自分たち）が決めた一貫した基準で付け、それを判定機に蒸留する。ラベルの基準が一貫していれば、判定機はそれをよく再現できる（MASSIVE 90%、DeepSeek のラベルとの一致率は livedoor で 85〜88%）
- **提案するアーキテクチャ**: LLM の判定を正当なものとし、問題があればナレッジ（定義・説明・例）を直す。人が異を唱えたら、埋め込みが近い文のうち判定が違うものを並べ、差分を言語化してフィードバックにする。言語化できて近い文にも一貫して当てはまれば定義違い、できなければ人のブレとして分ける。詳しくは [00_knowledge/05_architecture/](../00_knowledge/05_architecture/)
- **判定機の迷いは、基準のブレの印になる。** 国交省の自動車不具合情報で、確信度の低い申告ほど、埋め込みが近い申告の正解も割れていた。曖昧な申告を教師データから除いても精度は上がらず、迷うべきところで迷わなくなった。件数を集計するときは、1 つに決めずに確率で按分すると、正解の件数とのずれが 144 件 → 55 件に減った。主張としてのまとめは [00_knowledge/06_claims/](../00_knowledge/06_claims/)

## 次にやること

- 国交省の自動車不具合情報（2022〜2025 年、11,862 件）で、装置名を正解にして蒸留を試す。装置名と、LLM が作ったカテゴリー案とで、判定機の迷いやすさを比べる
- few-shot の例の数を変える（1 / 5 / 20 件ずつ）。例の数と、同じ件数を人が付けて直接学習した場合の正解率を並べ、LLM を通す意味がある範囲を確かめる
- 話題で分ける場合は、取得する案件を増やす（今は 761 件のうち意見が取れたのは 249 件。結果公示案件は 5,534 件ある）
- 埋め込みを速くする（長い文の切り詰め、文の長さで並べ替えてから埋め込む）
- DeepSeek でラベルを付ける件数を増やす（5,000 件、train 全件など）。確信度で絞ったときの回答率が上がるか確かめる
- 本番で使うしきい値の決め方を考える（正解のラベルがないので、少数を人がチェックして決める）
- ラベルの質を上げる（思考ありにする、`deepseek-v4-pro` を使う、グループの説明を改善する）と、判定機の精度がどこまで上がるか試す
- 本番に近い形として、グループを渡さずに LLM にグループ分けから考えさせる方法を試す
