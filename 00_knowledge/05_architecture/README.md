# 提案するアーキテクチャ: LLM の判定を基準にし、異議は言語化して定義に戻す

Phase 2（蒸留）の実験から出した、判定機の作り方と直し方の提案。

## 前提（実験でわかったこと）

- 自然言語のラベル付けは、人がやっても判断がブレる。1 件に、どれも筋の通るカテゴリーが複数あることが多い
  - livedoor で DeepSeek と正解が食い違った記事を 15 件読むと、DeepSeek のはっきりした間違いは 2 件だけだった
- 人のブレに、説明だけで追いつくのは無理。説明だけの DeepSeek は 64%、例を 5 件ずつ見せても 71% で止まった
- LLM の判定はほぼ揺れない。同じ条件で付け直しても 96% 前後一致した
- 判定機（埋め込み＋ロジスティック回帰）は、一貫した基準のラベルならよく再現できる。MASSIVE で 90%、livedoor で DeepSeek と 85〜88% 一致した

詳しい数字は [04_worklog/](../../04_worklog/) と [03_results/](../../03_results/)。

## 基本の考え方

1. **LLM の判定を正当なものとする。** 基準は人の気分ではなく、LLM に渡すナレッジ（カテゴリーの定義・説明・例）で決まる
2. **判定に問題があるなら、個々のラベルではなくナレッジを直す。** 直したナレッジで LLM がラベルを付け直し、判定機に蒸留し直す
3. **人が LLM の判定に異を唱えたら、その場でラベルを書き換えず、言語化させる。** 埋め込みが近い記事のうち判定が違うものを並べ、どこが違うのかを明示的な言葉にする。言葉にできたものだけをナレッジに戻す
4. これで、人の異議が**ブレ**なのか、**本当の定義違い**なのかを分ける

## 流れ

```
            ナレッジ（カテゴリーの定義・説明・例）
                  │                         ▲
                  ▼                         │ 定義違いなら、言語化した差分を足す
  文 ──▶ LLM がラベルを付ける ──▶ 判定機に蒸留 ──▶ 本番の判定（速い・ローカル）
                                                    │
                                                    ▼
                                          人が異を唱える（この判定はおかしい）
                                                    │
                                                    ▼
                         埋め込みが近い文を集める（同じ判定のもの・違う判定のもの）
                                                    │
                                                    ▼
                             並べて、何が判定を分けるのかを言葉にする
                                   │                            │
                    一貫したルールとして言える           言えない・近くの文と矛盾する
                                   │                            │
                                   ▼                            ▼
                             定義違い → ナレッジを直す       ブレ → LLM の判定のまま
```

## 異議の扱い方

人が「この文のラベルは X ではなく Y だ」と言ったとき:

1. **近い文を並べる。** 異議の出た文の埋め込みに近い文を、LLM の判定が X のものと Y のものに分けて数件ずつ出す
2. **差分を言葉にする。** 「Y にすべき文」と「X のままでよい文」を分けるルールを、人（または LLM）が文章で書く。例:「製品の発表でも、価格や発売日が中心なら家電、使い方が中心なら IT」
3. **ルールを近い文に当てる。** 書いたルールで、並べた文を判定し直す
   - ルールが近い文にも一貫して当てはまり、人の他の判断とも矛盾しない → **定義違い**。ルールをナレッジに足し、LLM で付け直して蒸留し直す
   - ルールが書けない、または近い文で人自身の判断と矛盾する（似た文なのに X と言ったり Y と言ったりする） → **ブレ**。LLM の判定のままにする
4. **記録する。** 異議、並べた文、書いたルール、どちらと判断したかを残す。同じ異議が何度も出るなら、ナレッジの穴の候補になる

## 良いところ

- 基準が言葉として残る。ラベルを個別に直すと、何が変わったのか誰にもわからなくなる
- 一度直したナレッジは、近い文すべてに効く。1 件ずつ直すより手間が少ない
- 人の気分を正解として学習しないので、判定機がブレを覚えない
- 判定機は蒸留し直すだけで更新できる。埋め込みは文ごとに 1 回でよい

## 試した結果

livedoor の家電・IT・スマートフォンで、異議の流れを試した（人の異議は正解のラベルで代用。[03_results/04_livedoor/03_feedback_rules.md](../../03_results/04_livedoor/03_feedback_rules.md)）。

- 3 つの組み合わせとも「ブレ」と判断した。2 つは、近い記事を並べると人の判定が逆になっている例が多く、LLM 自身が一貫したルールは書けないと答えた
- 1 つはルールが書けたが、言語化に使っていない記事に当てると 1 件も直らなかった。その場の例にだけ合う、後付けの説明だった
- 近い記事に当てて確かめる手順がないと、この後付けの説明をナレッジに入れてしまっていた
- 独身女性のコラム / 女性向けでは「定義違い」と判断できた。「題材が美容でも、働く独身女性の体験や本音の語りが主軸ならコラム、情報やハウツーなら女性向け」というルールで、言語化に使っていない記事の異議 30 件のうち 12 件が直り、壊れたものは 0 件だった（[04_feedback_rules_dokujo.md](../../03_results/04_livedoor/04_feedback_rules_dokujo.md)）
- 独身女性のコラム / 映画は、ルールはもっともらしく書けたが 1 件も直らず、採用しなかった。ルールが書けることと、LLM がそれに従って判定を変えることは別
- 採用したルールを足し、判定がその境目の 2 カテゴリーだった記事だけ（全件の約 2 割）付け直して蒸留し直すと、評価用で先生は 70.7% → 72.0%、判定機は 71.3% → 72.5% になった。確信度 0.9 以上で答えられる割合は 56% → 68% に増えた（[05_distill_shots5_rules.md](../../03_results/04_livedoor/05_distill_shots5_rules.md)）
- 付け直しは、ルールが関わる境目の記事だけでよい。料金は全件の約 5 分の 1 で済んだ

## 未確認のこと

- 近い文を何件並べれば、ブレか定義違いかを判断できるか
- 差分の言語化を、人ではなく LLM にどこまで任せられるか
- ナレッジが長くなりすぎたときの扱い（ルール同士の矛盾、プロンプトの長さ）
