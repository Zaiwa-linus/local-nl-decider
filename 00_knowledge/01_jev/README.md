# jev（TypeSafe AI）

2026-10-29 時点で、公式ドキュメント（https://docs.typesafe.ai/introduction）と規約を読んでまとめたメモ。
早期アクセス中のサービスなので、仕様や価格はすぐ変わる可能性がある。ドキュメントの全ページの一覧は https://docs.typesafe.ai/llms.txt にある。

## 規約上の制約（重要）

Master Customer Agreement（https://typesafe.ai/legal/mca）より。

- **§2.3(b): jev の出力を使ったモデルの蒸留（distillation）は禁止。** jev の出力をまねるようにモデルを学習させることも禁止
- **§2.3(b): jev の出力を、似たサービスや競合するサービスの開発に使うことも禁止**
- §2.3(c): リバースエンジニアリングの禁止
- §4.2: 出力の権利は利用者に帰属する（TypeSafe は所有権を主張しない）
- §4.1: 利用者のデータを、同意なしに学習データに入れない。モデルの説明でも「お客様のリクエストやレスポンスでは学習しない」とされている

**このプロジェクトへの影響**: 「jev にラベルを付けさせ、そのラベルで判定機を学習する」という使い方は、§2.3(b) の「出力をまねるようにモデルを学習させる」に当たる可能性が高い。そのため、**jev の出力を学習データには使わない**。

規約上問題がない使い方の例: ローカルの判定機の確信度が低かったものだけを jev に判定させる（判定を jev に回すだけで、jev の出力では学習しない）。

## 概要

- TypeSafe AI の「System One」と呼ばれる判定用のモデル。文章を生成する LLM ではない
- 判定したい内容（`state`）と型の決まった質問を送ると、型の決まった答えと確率の分布が返ってくる
- 判定の理由は説明しない。文章も書かない
- タスクごとの学習はいらない。質問と選択肢を書けばそのまま使える（ゼロショット）
- **言語**: 主に英語で学習されていて、英語がいちばん精度が高い。日本語などの CJK 言語は、英語ほど安定しない（公式の説明）

## モデル

| | Jev 1.14 | Jev 1.13 |
| --- | --- | --- |
| モデル ID | `jev-1.14.0` | `jev-1.13.0` |
| 公開日 | 2026-10-14 | — |
| 価格（入力） | 100 万トークンあたり $0.042 | 同じ |
| 価格（出力） | 無料 | 無料 |
| コンテキスト | 1 リクエスト 64k、1 質問 32k（ロングコンテキスト用のヘッダーを付けると 262k） | 同じ |
| 入力 | テキストのみ | テキストのみ |

- `jev-latest` は今は `jev-1.14.0` を指す。`jev-preview` も今は同じものを指す
- 別名は新しい版が出ると中身が変わる。結果を安定させたいときは `jev-1.14.0` のように版を指定する
- 1.14 での変更点は公開されていない

## 質問の種類

| type | 用途 | `criteria` | 返ってくる値 |
| --- | --- | --- | --- |
| `choice` | 選択肢から 1 つ選ぶ | 必須。`{選択肢名: 説明}`、1〜255 件 | `choice`, `confidence`, `probabilities` |
| `noul` | はい／いいえ | 任意。`{"true": 説明, "false": 説明}` | `noul`（「はい」の確率、0〜1） |
| `score` | 段階で評価する | 必須。段階の説明を並べた配列、最大 10 件（先頭が 0 点） | `score`（期待値）, `confidence`, `legend`, `probabilities` |
| `box` | 画像の中の位置を返す | — | `box`（top/bottom/left/right） |

- 1 回のリクエストに複数の質問を入れられる。質問はそれぞれ独立に、並行して判定される。質問を増やしても応答時間はほとんど増えない
- 質問 ID（`questions` のキー）はモデルには見えない。選択肢の名前と説明は見える

### choice の書き方（公式のおすすめ）

- 選択肢の説明は、ほかの選択肢と区別できるように書く。まずは 1 行の説明から始める。紛らわしい選択肢だけ、「対象」「対象外」「例」などを持つオブジェクトにする
- 当てはまらない入力がありうるなら、`other`（その他）の選択肢を入れる
  - ただし、その他だけに頼るのはよくない。別に `noul` の質問（「〜に当てはまるか」）を立てて、はいのときだけ choice の答えを使う
- 候補を絞り込まずに、すべての選択肢を渡す
- 複数のラベルを付けたいときは、観点ごとに choice を分けるか、確率がしきい値（例: 0.25）を超えた選択肢をすべて拾う
- 階層のある分類は、階層ごとに choice を重ねる（上位 K 件の候補を残しながら下りていく）

### confidence（確信度）

- `probabilities` の分布の「とがり具合」を 1 つの数にしたもの（0〜1）。1 に近いほど 1 つの選択肢に確率が集中している
- choice の確信度は、いちばん高い確率だけで決まる。例: (0.6, 0.3, 0.1) と (0.6, 0.2, 0.2) はどちらも 0.4
  - つまり確率そのものではない。確率 0.6 のときの確信度は 0.4
- **「当たる確率」として補正されているとは書かれていない**。しきい値は、自分たちのデータで確かめて決める
- 公式のおすすめの使い方: 高い → 自動で処理する、中くらい → 確認してから処理する、低い → 人に回す。しきい値はリスクに合わせて変える

## API

- エンドポイント: `POST https://api.typesafe.ai/v1/systemone`
- 認証: `Authorization` ヘッダーに `Bearer <API キー>` を入れる
- 使えるモデルの一覧: `GET /v1/models`（今は別名だけが返る）
- ストリーミングはない

### リクエストの中身

| フィールド | 必須 | 内容 |
| --- | --- | --- |
| `model` | ○ | `jev-latest`、`jev-1.14.0` など |
| `state` | ○ | 判定したいテキスト（文字列・オブジェクト・配列のどれでもよい） |
| `questions` | ○ | 名前を付けた質問の一覧（1 つ以上） |
| `assets` | | 画像（使う場合のみ） |

### レスポンスの中身

| フィールド | 内容 |
| --- | --- |
| `model` | 実際に答えたモデル（`jev-latest` を指定すると `jev-1.14.0` など） |
| `answers` | 質問の名前ごとの答え。中身は上の「返ってくる値」 |
| `usage` | `input_tokens`（課金対象）と `output_tokens`（無料） |

### 制限

- リクエストの本文は最大 32 MiB。gzip / zstd で圧縮して送れる
- `state` や `criteria` の入れ子は最大 64 段
- レート制限は組織ごとにコンソールで設定されている。具体的な数字は公開されていない

### エラー

| ステータス | 意味 |
| --- | --- |
| 400 | リクエストのルール違反。コンテキスト長を超えたときもこれ（`max_tokens_exceeded`） |
| 401 | API キーがない、または間違っている |
| 413 | 本文が 32 MiB を超えた |
| 422 | 入力の検証エラー（必須の項目がないなど） |
| 429 | レート制限を超えた。少し待って再試行する（指数的に待ち時間を延ばす） |
| 529 | サービスが混んでいる。少し待って再試行する |

## Python SDK

- パッケージ名は `typesafe-sdk`（使うときは `uv add` で入れる）
- 環境変数 `TYPESAFE_API_KEY` を読む
- 同期版（`TypeSafeClient`）と非同期版（`AsyncTypeSafeClient`）がある
- 429 / 529 の再試行は SDK が自動でやってくれる

## API キー

- コンソールで作る（今は招待制）
- このリポジトリでは `.env` に `TYPESAFE_API_KEY=...` として置く（`.gitignore` 済み）。スクリプトは `uv run --env-file .env` で実行する

## 苦手なこと（jev-1.13 について公式が挙げているもの）

| 苦手なこと | 対策 |
| --- | --- |
| 指示を文字どおりに受け取る | 条件をはっきり書く。境目のケースを criteria に書く |
| 数を数えること、数値の表現（16 進数など） | コードで数える。意味のある名前や数に直して渡す |
| 日付や時間の比較 | 日付の部品を choice で取り出し、コードで計算する |
| 二重否定や、何段階もの推論 | 直接的な指示にする |
| 関係ない文章が多い | 先にコードで絞り込む |
| 悪意のある文章に誘導される | criteria をはっきり書き、事前にテストする |
| 指示と criteria が食い違う | criteria を指示の延長として書く |
| **選択肢の順番（最初の選択肢を選びやすい）** | 順番を入れ替えても答えが変わらないか確かめる |
| 文章の生成 | 候補は別の方法で作り、jev には選ばせるだけにする |

## このリポジトリで試した結果

- MASSIVE のシナリオ（18 種類）を 20 件だけ判定させた（動作確認）: 正解との一致 17/20 件。1 件あたりの応答時間は平均 0.19 秒、入力は約 840 トークン
- 規約（§2.3(b)）のため、このラベルは学習には使わずに削除した
